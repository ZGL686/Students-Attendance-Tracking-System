# Ludian 模拟器重启后恢复与启动入口

## 目标与原因

- 用户重启电脑后，恢复的浏览器标签页显示 `127.0.0.1:15473` 拒绝连接。
- 手机模拟器依赖本机 Vite 开发服务；重启会结束此前进程，浏览器恢复标签页不会自动恢复服务。
- 项目源码、模拟器 HTML、Node.js / npm 和依赖均存在，工作区恢复操作前干净。

## 实现

- 在项目根目录重新运行 `npm run dev`，Vite 固定监听 `127.0.0.1:15473`，继续使用 strictPort，避免端口漂移。
- 新增 `启动手机模拟器.cmd`，自动进入所在项目目录；现有模拟器入口正常响应时提示复用，否则检查 npm 和 Vite 依赖后调用相同开发命令。
- 启动入口在用户可控制的前台终端运行，显示固定地址和窗口保留说明；服务停止后保留提示。未添加开机自启或后台系统服务，也不会自动终止其他程序。
- README 增加重启后的操作方式及 `ERR_CONNECTION_REFUSED` 原因；继续使用原有 `127.0.0.1` 地址以保留浏览器数据空间。

## 验证

- Vite 输出 ready，模拟器入口与嵌入预览入口均返回 HTTP 200，HTML 包含正确的入口脚本路径。
- 运行 CMD 入口验证已运行服务的复用路径，输出固定地址，按键后以退出码 0 结束，未重复启动服务器。
- `npm run check` 通过：ESLint、92 个模块架构边界、Prettier、TypeScript。
- 本轮没有业务源码或存储逻辑修改，未运行涉及真实学生数据的自动化检查。
- 内置浏览器错误页的自动操作被协议安全策略拦截；本轮以服务响应确认恢复，页面需用户在原标签手动重新加载，不将 HTTP 响应等同于实际浏览器视觉验收。

## 结果与待确认长期记忆

- 本地开发服务已恢复，用户可刷新原地址；下次重启后可双击根目录启动入口。
- 前台运行期间保留启动终端；关闭终端或重启电脑后仍需重新启动服务。
- 未通过重启整台电脑验收，未修改个人数据、SQLite、应用标识或构建 Windows / Android 安装包。
- 暂无新增待确认长期选型。
