# Ludian 批量并集导入与识别进度提速

## 目标与已确认需求

- 用户报告离线 OCR 反复回到 0%，疑似循环；要求提高图片和文件识别速度及准确率。
- 用户进一步明确多张图片一起选择，合并全部有效安排后一次追加；可混选目录、课表、Excel / CSV 和 PDF。
- 继续离线处理、目录暂存、最新学期全周推断、重复与冲突提示，以及已有课程、学生和历史考勤保留。首先交付手机模拟器。

## 诊断与实现

- 没有发现循环重新发起导入：主要问题是每个局部 OCR 的 0–100% 直接覆盖总进度，清晰课程也被强制执行全部放大与字段扫描。原图基线为 270 次识别、52.91 秒和 311 次进度回退。
- `import-progress` 保留版式、目录行、课程格及 PDF 页的明确阶段，将局部任务映射到连续区间；`readImportFiles` 再按批次文件数量累计。识别阶段最高 97%，保存阶段仍依赖事务结果。取消和失败后的晚进度被忽略。
- 先检查颜色边界与星期 / 节次轴，可靠时跳过整张课表 OCR；不可靠时整图回退并复用轴文字，不重复扫描已分析的标题和侧栏。目录中完整且词分数至少 90 的字段直接复用，其他字段继续局部重试。
- 课程格原尺寸和彩色反相灰度结果必须同时满足严格字段门限、名称与可靠目录唯一对应、排课及周次一致，才缩短识别。其他课程保留全部原尺寸、2 倍、3 倍和颜色 / 灰度复核；明确目录名称不再重复扫描名称区域。房号在两条路径中均独立英文复核，不放宽低置信度门限。
- 区域按原尺寸裁剪后编码，减少大图重复解码；目录及课表逐张解码并释放，准备结果仅保存文字与几何。PDF 可变画布默认不复用旧 PNG。
- `managed-ocr-worker` 对接随包 Tesseract 7 协议，在初始化前拥有原始 Worker；编码、引擎初始化、参数和识别各有 45 秒上限。超时、错误、取消立即拒绝并终止，晚消息无效。混合文字、中文区域与英文数字使用固定语言，准备结束释放混合语言 Worker，避免扫描后的语言反复重初始化。
- 重叠目录按规范化名称和代码合并可靠教师；真实不同代码和多个可靠教师保留歧义。批次草稿仍合并后一次事务保存，完全重复安排跳过，不增加业务字段，schema 3 和应用标识不变。

## 验证

- 同机、隔离浏览器、用户两张原图：191 次识别、34.54 秒，调用数量减少约 29%，时间减少约 35%，进度回退为 0。耗时是本机样本测量，不是实体手机或所有图片的速度保证。
- 原图仍为 13 条目录资料、11 个安排、9 个不同课程；全部名称、课程代码、星期、节次及教室逐项核对通过。重点长课跨度和同一课程多次排课保持正确。三项不可靠教师继续留空并提示。
- 虚构彩色课表覆盖图片顺序颠倒、目录补选、缩放压缩 JPEG、英文数字、离线无外部请求。400 × 866 手机模拟器整批一次保存、刷新保持及空学生名单通过。
- 三张课表、目录和 CSV 的并集在一个修订中新增四个安排、跳过一个跨格式重复；再次选择整批不写入。低置信度、取消、晚回调、超时重试、保存中止和旧修订冲突验证通过，已有课表 / 学生 / 历史考勤保持。
- `npm run check`、`npm test`、相关 26 项端到端测试与 `npm run build` 通过；网页构建准备 230 项离线资源。新增单元测试覆盖任务超时、原始 Worker 异常、严格快速门限、目录复用 / 合并、批次和 PDF 页面进度。
- 私人原图及诊断只在本机忽略目录；自动化使用虚构数据和全新浏览器上下文，没有写入实际用户模拟器或原生数据库。
