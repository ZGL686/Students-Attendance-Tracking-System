# Ludian 安卓图片课表定位与保存提示修复

## 反馈与诊断边界

- 用户确认手机安装版本为 0.5.7，并提供识别结束界面：课程名已识别，但所有课程因星期、节次无法可靠确定而跳过。该截图说明没有产生可保存的安排，没有显示 SQLite 写入失败。
- 原 0.5.7 APK 哈希及打包记录已核对；多图入口和离线资源存在。电脑手机预览的成功不能替代 Android WebView 的实际运行。
- 原轴定位只接受单个星期标签和完整数字节次。原图区域 sparse 识别可能缺轴，电脑常规路径通过整图 mixed 识别恢复；将原图轴标签局部淡化后可重现旧路径失败。用户手机具体 OCR token 未采集，因此不能宣称已获得该设备的全部底层原因。
- 没有修改用户手机数据库、浏览器真实数据，或把名单重新灌入已有工作台。

## 实现

- `image-layout.ts` 支持完整、连续的合并星期文字，保留至少三个一致锚点和跨列拒绝规则。对同票但明显错位的星期行与节次拟合保守拒绝，避免输入顺序改变课程位置；合理重复扫描仍接受。
- 新增 `axis-image.ts` 与 `read-grid-axes.ts`。顺序为原有区域识别、整图识别、必要时小区域增强。增强顶部灰字，隔离页眉行；侧栏排除宽时间行，仅对数字候选使用英语模型和数字白名单。重试数量有上限，保留原坐标，只同时持有一个顶部或侧栏小画布。
- `readImages.ts` 显示解码与增强定位阶段；异常包含文件名和实际阶段。保留单调批量进度、取消、最终释放及整批识别后一次保存。
- `image-canvas.ts` 采用 bitmap 优先及 Image/blob URL 兼容兜底；每种解码有 15 秒期限及取消竞速。迟到 bitmap 关闭，blob URL 和画布最终释放；保留原尺寸和 24MP 上限。
- `ImportCourses.tsx` 在全部跳过或重复时展示每项原因；补录区的已保存文案只在持久化成功后显示。保存失败、全部重复并部分冲突时不再声称其余课程已保存。仍沿用版本检查和事务，不放宽重复或时间冲突规则。
- 增加受版本控制的 `src-tauri/android/` 模板和构建准备脚本。Android Worker 子资源通过仅允许固定应用域 `GET /offline/` 的请求适配复用 Rust 资源响应；不增加外网访问或放宽 CSP。模板保留安全区处理，生命周期 owner 避免旧 Activity 清掉新注册。生成内容不同先备份，相同内容不重复写入。
- Worker 适配有 Chromium 底层路由依据及原生编译证据，属于独立兼容补强，不能作为本次截图的已确认故障原因。[Chromium Worker 路由源码](https://raw.githubusercontent.com/chromium/chromium/main/android_webview/browser/aw_content_browser_client.cc) 与 [请求客户端选择源码](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/android_webview/browser/network_service/aw_proxying_url_loader_factory.cc)。
- 源码版本更新至 0.5.8。应用标识 `cn.guilu.attendance`、schema 3、课程周次的最新学期事务推断及旧数据保留规则不变。Windows EXE / ZIP 仍为 0.5.6。

- 原生 Kotlin 编译与 4 项 JVM URL 策略测试通过。Cargo 离线测试 3 项通过，覆盖乐观版本保存、快照保留、旧版本兼容和损坏数据库保护。
