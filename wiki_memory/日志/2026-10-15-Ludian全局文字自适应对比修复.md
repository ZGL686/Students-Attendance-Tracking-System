# Ludian 全局文字自适应对比修复

源码、Android APK 与 Windows EXE / ZIP 已完成 0.5.11 构建及下列验证；实体 Android 手机尚未实测。

## 用户需求与边界

- 用户要求整个应用的文字适应不同背景，保持清楚易读，不能只修手机底部导航。说明、工具条、表单、按钮、提示及通知均在范围内。
- 自动处理文字与阅读底板，不增加用户设置或复杂操作；保留内置 / 自定义壁纸、玻璃透明度、明暗模式、字体、字号和动效偏好。
- 用户进一步强调成品美观；阅读卡片需有一致的圆角、留白与文字层级，搜索图标与输入字段内联，保留主题氛围和壁纸。
- 本轮源码、Android APK 与 Windows EXE / ZIP 统一更新为 0.5.11，业务 schema 3、应用标识 `cn.guilu.attendance`、本地数据及备份不变。手机保留 Excel / CSV 选择后自动保存与无 OCR / PDF 的范围，0.5.10 原生 Insets 处理继续保留。
- Windows 使用完整 `npm run release` 构建，需核验最终 EXE、ZIP 及解压版一致性。浏览器视觉验收、APK 编译或静态审计不能代替实体手机运行验证。

## 检查发现

- 玻璃透明度会将主题 surface 调成透明色，部分页面说明、工具条及辅助文字直接叠在壁纸上；只给考勤等数据卡片加不透明底色不能覆盖全部阅读区域。
- 经典浅色主按钮、部分主题选中 / 悬停区域与辅助文字存在对比不足，单独保证基础 surface 上的正文颜色仍不够。
- 深色主题的按钮前景 `onAccent` 为深墨色，但通知与工具提示错误地复用它配固定深灰底，形成深字深底。禁用按钮、已撤销记录及拖拽卡片的整容器 opacity 也会连同文字一起淡化。

## 本轮实现

- `src/preferences/readability.ts` 提供纯函数，结合普通底色、选中 / 悬停色及语义标签底色派生可读前景；优先保留原色倾向，必要时向黑或白调整。按钮默认 / 悬停 / 按下配对一并计算。
- 当前实现主文字目标 7.2、辅助及功能文字目标 4.65，为浏览器渲染保留余量；阅读底板透明度向上取整到 1/255，覆盖八位合成量化。26 项算法测试覆盖全部主题、0–70% 玻璃设置、黑白及中间亮度、语义文字和按钮配对。
- 壁纸保护按黑、白背景合成的亮度范围计算最坏对比；当前景落在可出现的背景亮度区间时按对比 1 处理，不能只测两个端点。自动增加阅读底板的不透明度；相互冲突的未来底色组合使用实体回退，避免以不满足的计算结果继续显示。
- 设备偏好应用流程派生运行时颜色与阅读底板，不修改用户保存的玻璃透明度或增加偏好字段。主线程的全局阅读样式为说明、工具条、页头与页面阅读分组提供底板；既有数据卡片和表格继续使用不透明底色。
- 阅读分组沿用主题圆角，统一留白与主次文字层级；手机搜索控件明确采用横向排列，放大镜与输入内容保持同一行。Skyhill 浅色 / 深色的记录便捷列表与完整数据库四张代表截图已目检，无文字重叠，分组与背景保持协调。
- `tokens.css` 新增通知、工具提示与禁用按钮专用配色，通知 / 错误通知 / 工具提示不再复用主题按钮前景。通知关闭按钮的悬停 / 按下保持相同可读配对。
- 禁用动作按钮采用实体灰底、清晰文字和边框，子文字继承对应前景；只读数据单元格保留自身语义。已撤销记录保留现有“已撤销”标签，以虚线区别状态；拖拽卡片同样使用虚线轮廓，均移除整容器淡化。
- README、使用说明、AGENTS 与当前状态页同步用户明确需求；算法、阈值和阅读层覆盖方式仍按候选技术方案维护，不因本次实现自动成为长期决策。

- 其余 32 项回归覆盖底部导航、安全区、放大字体、横屏、表格导入及备份；最终新矩阵输出位于本地忽略目录 `.local/contrast-0511-e2e/final`，不将截图提交 Git。
