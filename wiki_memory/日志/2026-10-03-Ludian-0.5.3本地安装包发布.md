# Ludian 0.5.3 本地安装包发布

- 目标：补齐原生构建环境，将本轮功能改进打入 Windows 与 Android，并覆盖用户本地最新发行文件。
- 本篇补充构建准备日志的后续结果；该日志所述构建环境及 Android 签名阻塞已按以下方式解决。

## 用户确认与结果

- 用户明确授权安装所需环境、覆盖本地安装包，并选择创建新 Android 发布签名的方案。
- 原签名私钥不可用，0.5.3 使用本次新建且保存在本机的签名。旧签名版本必须先将完整 JSON 备份保存到应用外，再卸载旧版、安装新版并导入备份。
- 固定包名仍为 `cn.guilu.attendance`，Android 版本号为 `0.5.3` / `5003`。后续发布必须复用本次签名，避免再次发生重装迁移。
- Windows 解压版 `Ludian-latest/Ludian.exe` 与 `Ludian-latest.zip` 已覆盖为 0.5.3；Android `Ludian-Android-universal.apk` 已覆盖为新签名 0.5.3。
- 密钥、密码、重签脚本和签名备份说明单独保存在本地发行工作区的 `.local/signing/`；未进入源码仓库或安装包。尚需用户在独立受控位置备份整个目录。

## 构建及文件变更

- 补齐 JDK 17、Android SDK/NDK、Gradle、Rust Android targets 和 Windows C++ 构建工具，完成 Windows 原生 release 与 Android ARM64 / ARMv7 release 构建。
- 使用经过官方 SHA256 核对的本地 Gradle 发行包，解决构建下载失败；修正本地生成的 Android BuildTask 对 Tauri CLI 的相对路径，完成 Gradle 对 Rust 构建的调用。
- 本地重签脚本复用密钥，依次执行对齐、签名、证书与版本检查，原子替换 APK 并更新 `android-version.json`。创建密钥操作拒绝覆盖已存在的签名资料。
- 补充发行目录中的 Android 安装迁移说明和签名资料备份说明。
- 生成目录、构建工具、签名资料及二进制发行文件不提交 Git；本次仓库更新为日志、索引及用户已确认的签名约束。

## 检查摘要

- Windows ZIP 内 EXE 与解压版 EXE 的 SHA256 一致；版本清单为 0.5.3。
- Android `apksigner verify` 成功，v2 / v3 签名有效，APK 证书与本地签名证书一致。
- Android ZIP 16 KB 对齐检查成功；包名、版本、最低 API 24、ARM64 与 ARMv7 本地库检查通过。
- EXE SHA256：`8ea38a45329edfdfcc7d9093b5c737b46e3a6e3e0b186a860b8fcafa106162b6`。
- ZIP SHA256：`5140ccf634e6a46daf0bf8d36e6cdcc5956dca902434339928128ecbfdb73b5f`。
- APK SHA256：`a5d723177fac41a21e5f928f235b51e15353350d239e2fed52fdc8eaf46434b0`。
- 本轮完成原生构建与发行文件检查，未进行实体手机运行验收，不将构建成功视为用户功能验收。

## 遗留与下一步

- 用户独立备份签名资料；手机旧版先完整导出数据再卸载重装。
- 用户在实际设备核对课表导入、壁纸、离线数据、备份恢复和系统返回交互。

## 待确认长期记忆

- 无新增未确认选型。用户已明确选择新签名，其迁移要求与后续复用要求同步至当前约束和待办；本地工具缓存及生成工程修补只记录在本日志。
