# 本地数据保存

## 背景

用户要求跨版本保留考勤，允许完整备份恢复，业务数据与程序目录分离。

## 初版选择

桌面采用 SQLite 追加快照事务，WAL、FULL 同步、期望版本号防止旧数据覆盖。浏览器采用 IndexedDB 事务。只有数据库没有快照时初始化，未知版本或损坏不得自动重建。

完整备份为带 SHA-256 校验的版本 1 JSON。导入验证结构与完整性后恢复为工作台副本，保留原工作台和已撤销记录。

2026-09-28 用户确认 Android 复用本地 SQLite/schema 3，不连接云端；手机和 Windows 通过完整 JSON 手动迁移。手机首次导入保留 Windows ID；后续 Windows→手机更新名单和课程并保留手机考勤；手机→Windows 只按工作台 / 记录 ID 合并新增考勤，冲突默认保留 Windows 并允许逐条选择，不按快照缺项删除数据。备份保持未加密，按本机受控方式传递。

## 影响

实现直接、历史可核对，代价是磁盘占用增长，后续可讨论归档策略。数据库未加密，依赖本机账户权限。

## 验证

Rust 测试覆盖提交、过期版本、重新打开及损坏文件；浏览器端到端测试覆盖记录与备份往返；独立桌面目录验证 WebView2 和 SQLite。

## 状态

此为用户确认的本地保存方向。Android APK 的原生签名、设备端持久化与迁移行为仍待工具链和设备验收。
